# VER-002：Skill 与知识卡的版本历史界面

- ID：VER-002
- 阶段：E
- 目标：在 Skill 编辑器与知识卡面板提供可用的本机历史：列出版本/修订、查看摘要、一键回滚（调用 VER-001 API）。用户能看见“回滚会新增一条历史，而不是删掉旧版本”。
- 负责人 Agent：frontend_engineer（BookSkill Frontend Engineer）
- 依赖：VER-001（API 与迁移）。在 VER-001 开出 PR 且接口签名稳定后开工；不得自己实现第二套历史存储。SKILL-001 若已合入，在其 Skills 面板上追加历史；若尚未合入，可在本票分支以 `origin/integration` 为底，把历史面板做到知识卡，并为 Skill 预留同样组件。
- 状态：Ready（排队，待 VER-001 接口稳定）
- 启动时间：2026-11-16 22:10 Asia/Shanghai
- 分支 / 工作树：从当时的 `origin/integration` 或含 VER-001 接口的约定底拉 `feat/VER-002`，独立 worktree `/workspace/bookskill-worktrees/VER-002`（开开工时再由 Frontend 从最新底创建，若 worktree 已由 Orchestrator 按 integration 建好，先不要改 data 层）
- 风险等级（预估）：中（只接线已有 API；不改 schema）
- 测试样本：只使用 FIXT-001 或同等许可/合成样本。

## 允许写入

- `packages/desktop/src/renderer/skills/**` 中的历史面板（若与正在进行的 SKILL-001 冲突，等 SKILL-001 PR 开出后再基于该分支或 integration 变基，禁止两人同时改同一文件）
- `packages/desktop/src/renderer/knowledge/**` 仅允许**追加**历史/回滚 UI 与测试，不得改确认/合并/删除契约
- desktop main / preload 仅允许**追加** history/rollback IPC
- `docs/versioning/**`

## 禁止写入

- `packages/data`、VER-001 的核心 API 文件、搜索/关系实现、FIXT、治理文件
- 回滚操作不得绕过 D-017 / D-018（UI 不得把“回滚”做成“自动确认”或“自动发布”）
- 不得合入 `main`，不得发布，不得推进网盘分发

## 验收条件（可测试）

1. 对一张编辑过的知识卡，历史列表至少显示 2 条修订；选择较早修订并回滚后，界面展示恢复后的正文，状态不会变成已确认，除非用户再点确认。
2. 对一个有至少 2 个版本的 Skill，历史列表可显示版本号与时间；回滚后当前版本号变为新行，旧版本仍列在历史中。
3. 回滚失败（未知 id）有明确错误，不损坏当前数据。
4. 自动化测试覆盖上述路径；失败时非零退出。独立 QA 通过后才能合入 `integration`。不得宣布完成，除非独立 QA 验证通过。
