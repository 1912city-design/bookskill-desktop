## 验收条件（可测试）

1. **隐藏联系可被发现**：对至少两张已存在的知识卡，在满足下列条件之一时，`discoverKnowledgeRelations`（或同等命名）能提出建议，且确认前不得出现在“已确认关系”列表中：
   - 共用来源段落（同一 `source_chunk_id` 或同一段落 locator）；
   - 标题/正文有可复现的本机相似度（测试中用固定合成文本，阈值写在报告里）；
   - 类型规则（例如案例 → 原则，默认为 `example_of`）。
   每条建议必须带简短、可测试的理由字段（例如 `shared_source` / `text_overlap` / `type_rule`），供 UI 展示。
2. **D-017**：发现函数本身不得写入 `verified_by_user`。只有既有 `confirmRelation`（或明确的用户确认 IPC）可以。自动化测试必须直接断言发现结果的 status 全是 `suggested`。
3. **幂等与去重**：对同一对卡片、同一 `relation_type`，重复运行发现不得产生重复的待确认建议；不得覆盖或复活已确认关系；已驳回的同一对+类型不得被自动再次插入为 `suggested`（测试覆盖）。自环必须拒绝。
4. **用户确认/驳回**：确认后成为正式关系，类型属于 `supports` / `contradicts` / `example_of` / `related_to`。驳回后不得残留为正式关系。
5. **删除契约**：删除任一端知识卡时，既有删除契约仍成立（相关关系行被清理）。
6. 自动化测试覆盖发现 → 确认、发现 → 驳回、重复发现、已驳回不再自动建议、非法自环；失败时非零退出。独立 QA 通过后才能合入 `integration`。不得宣布完成，除非独立 QA 验证通过。
